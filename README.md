# UI-автотесты Demo Web Shop

Проект по ТЗ на Python, Playwright, pytest и Allure. В [исходных кейсах](incl.tex) описана Стройудача. В её форме входа обнаружена невидимая Google reCAPTCHA v3 для действия `login_phone`. Поэтому по разделу 01 ТЗ выбран Tricentis Demo Web Shop. [Форма входа учебного магазина](https://demowebshop.tricentis.com/login)

В учебном магазине доступен вход по email и паролю. Телефон используется в адресе заказа. Позитивные сценарии подтверждают переход на главную и проверяют email авторизованного пользователя в шапке. Негативные проверяют сообщение формы, отсутствие ссылки выхода и данных аккаунта. Для неверного пароля кейс также проверяет успешный вход после исправления.

## Запуск

Для запуска с видимым окном Chromium выполните эту команду из любой папки. Скрипт установит зависимости, запустит все десять тестов и напечатает путь к свежему HTML-отчёту.

```sh
/home/alter/study/testirovanie/run-demo.sh
```

Чтобы быстро посмотреть только сценарий заказа, добавьте `-m order`. Для проверок входа используйте `-m auth`. Окно Chromium показывает действия во время прогона. После него откройте [Allure-отчёт](artifacts/allure-report/index.html) в браузере.

Для показа скриншота при падении запустите `./run-demo.sh -k TC-A-03` из корня проекта. В Allure откройте кейс «Пустой email · демонстрация падения» и вложение «Состояние страницы · call».

Нужны Python 3.11+, `uv`, Node.js и Java 17+. Версии Python-зависимостей закреплены в [uv.lock](uv.lock). Для запуска вручную из корня проекта используйте `SHOP_HEADED=1 uv run pytest autotest`.

## Данные и конфигурация

По умолчанию фикстура регистрирует нового учебного пользователя через UI, выходит из него и начинает каждую проверку в отдельном браузерном контексте. Для заказа используются вымышленные контакты из [data/demo.toml](data/demo.toml). При использовании подготовленной учётной записи нужна пустая корзина. Для сценария оформления используйте новый аккаунт без сохранённых адресов.

| Переменная | Назначение |
| --- | --- |
| `SHOP_BASE_URL` | Адрес совместимого учебного стенда, по умолчанию `https://demowebshop.tricentis.com` |
| `SHOP_BROWSER` | `chromium` по умолчанию, также `firefox` и `webkit` после установки браузера |
| `SHOP_SLOW_MO_MS` | Пауза между действиями Playwright в миллисекундах, для демозапуска по умолчанию 500 мс |
| `SHOP_HEADED` | Значение `1` показывает окно браузера |
| `SHOP_BROWSER_EXECUTABLE` | Необязательный путь к установленному браузеру для локальной проверки |
| `SHOP_TIMEOUT_MS` | Тайм-аут действия и проверки, по умолчанию `30000` мс |
| `SHOP_NAVIGATION_TIMEOUT_MS` | Тайм-аут навигации, по умолчанию `35000` мс |
| `SHOP_DATA` | Путь к TOML, по умолчанию `data/demo.toml` |
| `SHOP_EMAIL`, `SHOP_PASSWORD` | При необходимости оба значения передаются через окружение |
| `--log-cli-level` | Опция pytest для уровней `DEBUG`, `INFO`, `WARN`, `ERROR` |

Шаги Allure и параметры содержат ID кейсов, варианты проверок и данные товара. На падении прикладывается скриншот с закрытыми полями и блоками контактов либо причина, по которой снимок недоступен. Браузерные трассировки, HTML и HTTP-данные в отчёт не добавляются.

## Адаптация кейсов

| ID из исходной работы | Самостоятельные наборы | Ожидаемый результат на новом стенде |
| --- | --- | --- |
| TC-A-02 | Кнопка `Log in`, клавиша Enter | Переход на главную с сессией нужного пользователя |
| TC-A-03 | Пустой email, демонстрация падения | Тест ожидает `Please enter your email`. Стенд отвечает `No customer account found`, поэтому Allure отмечает кейс как Failed и прикладывает скриншот |
| TC-A-04 | Пустой пароль | Отказ формы входа, гостевая сессия |
| TC-A-05 | Без `@`, без локальной части, без домена | Сообщение о формате email, гостевая сессия |
| TC-A-06 | Другой пароль | Ошибка входа и гостевая сессия, затем успешный вход после исправления |
| TC-A-07 | Уникальный незарегистрированный email | Ошибка входа, гостевая сессия |
| TC-M-03/08/09/16 | Один сквозной тест под ID TC-M-16 | Поиск по названию, карточка, корзина, доставка и заказ с оплатой при получении |

В поиске ожидается результат с точным названием `Computing and Internet`. Допустимы другие результаты, содержащие запрос. Товар продаётся по 10.00 за штуку, количество 2, сумма товаров 20.00. Варианты товара для этой позиции отсутствуют. Стенд предлагает доставку Ground и оплату Cash On Delivery. Стоимость доставки, сбор за оплату и налог берутся из сводки заказа, чтобы сверить расчёт итоговой суммы и её сохранение в деталях заказа. 

### TC-M-16 · Шаги сквозного сценария

1. Войти как новый учебный покупатель. На главной отображается его учётная запись. Корзина пуста.
2. Выполнить поиск по названию. Среди релевантных результатов есть карточка `/computing-and-internet` с ценой 10.00.
3. Открыть карточку и проверить название, цену и статус `In stock`. Добавить 2 экземпляра. Стенд показывает подтверждение добавления.
4. Проверить одну строку корзины и сумму товаров 20.00. Принять условия продажи и перейти к оформлению.
5. Заполнить платёжный адрес и контакты, использовать тот же адрес для доставки, выбрать Ground и Cash On Delivery. Сверить строку товара и расчёт итога, затем нажать Confirm.
6. Дождаться сообщения об успешном создании и открыть детали заказа по ссылке. Сверить номер, товар, количество, цену, контакты, доставку, оплату и итог с предыдущими шагами.

## Результат исходной проверки

При первичной проверке в Chromium прошли девять сценариев авторизации и сквозной сценарий. Стенд создал демозаказ №2421885 на 27.00. HTML-отчёт по ссылке выше показывает результаты последнего запуска скрипта.
